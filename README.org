Automatic capitalization with batteries included.

* Getting started
** Requirements
The package requires emacs version 28.1+.

=auto-capitalize-org.el= requires ~font-lock~ to detect comments and strings in ~org-mode~
src blocks. ~org-src-fontify-natively~ must therefore be non-nil, and org itself must be of
version 9.8 at least.

=auto-capitalize-tex.el= requires [[https://www.gnu.org/software/auctex/][AUCTeX]], and it will not work with the builtin ~tex-mode~ and
its derived modes.

** Installation

*** Get it from MELPA

The easiest way to get ~auto-capitalize.el~ is from MELPA:

1) If you don’t have MELPA set up already, [[https://melpa.org/#/getting-started][it’s easy to do so]].
2) Once your ~package.el~ can talk to MELPA, you can simply say

   ~M-x package-install RET auto-capitalize RET~

*** Get it from this repo
**** With ~package-vc~
If you’re on emacs 29.1+, you can install ~auto-capitalize~ directly from this repo with
emacs’s builtin ~package-vc~:

~M-: (package-vc-install "https://github.com/abdulnafe-t/auto-capitalize.el") RET~

This will clone the repo directly into your elpa directory and works much the same as
installing from MELPA. The main difference is that VC packages are not upgraded along with
the rest: you will need to call ~package-vc-upgrade~ or ~package-vc-upgrade-all~ for that.

**** Manually
Of course, there’s always the good old way of cloning the repo or downloading [[https://github.com/abdulnafe-t/auto-capitalize.el/releases][the latest
release]] manually and putting the files somewhere your emacs can find them. For example,
you could run this in a terminal:

#+begin_src sh
git clone https://github.com/abdulnafe-t/auto-capitalize.el ~/.config/emacs/elpa/auto-capitalize
#+end_src

Then put this somewhere in your =init.el=:

#+begin_src elisp
(add-to-list 'load-path "~/.config/emacs/elpa/auto-capitalize/")
(require 'auto-capitalize)
#+end_src

** Enabling auto-capitalize-mode
If you use ~use-package~, you can use this snippet:

#+begin_src elisp
  (use-package auto-capitalize
    :init
    (auto-capitalize-global-mode))
#+end_src

That’s all you need to get capitalization in ~prog-mode~ buffers, both traditional and
treesitter-based, and ~text-mode~ buffers that don’t have any special markup syntax. You’ll
need a plugin for the ones that do.

** Enabling plugins
By itself, ~auto-capitalize-mode~ makes too many mistakes in markup documents, and so
~auto-capitalize-global-mode~ does not enable it in such modes. Plugins solve this problem
by teaching ~auto-capitalize-mode~ about specific markup rules. Currently, there are four
such plugins: =auto-capitalize-org.el= for Org, =auto-capitalize-tex.el= for TeX/LaTeX,
assuming you have ~AUCTeX~, =auto-capitalize-sgml.el= for SGML (and its derivatives, like
HTML)., and =auto-capitalize-xml.el= for XML.

To make use of these plugins, simply add the corresponding minor mode to the appropriate
hook:

#+begin_src elisp
  (use-package auto-capitalize
    :init
    (auto-capitalize-global-mode)
    :hook
    ((TeX-mode . auto-capitalize-tex-mode)
     (org-mode . auto-capitalize-org-mode)
     (sgml-mode . auto-capitalize-sgml-mode)
     (nxml-mode . auto-capitalize-xml-mode))
#+end_src

This will give you markup-aware capitalization in those modes, such as capitalizing text
inside of any TeX macro listed in ~auto-capitalize-tex-macro-whitelist~, not capitalizing
HTML tags, preventing capitalization in TeX math environments, etc.

And that’s pretty much it. Start typing to try it out! And if it ever capitalizes (or
downcases) a word in a way you don’t like, you can simply undo (~C-x u~ by default) to
revert that capitalization.

* Customization

Things should just work for most users, with sensible defaults. ~auto-capitalize-mode~
respects your settings such as ~sentence-end-double-space~ and ~paragraph-indent-minor-mode~,
and should work fine with both traditional modes and treesitter-based ones. However, there
are customization options in the ~auto-capitalize~ group, which should let you get the exact
behavior you want.

If you want to limit auto-capitalization to certain modes instead of enabling it globally,
replace ~auto-capitalize-global-mode~ in the snippets above with ~auto-capitalize-mode~, which
is the buffer-local version. You can add that to any mode’s hook you want. For example, to
only enable =auto-capitalize.el= in text-mode buffers, but not prog-mode, you could say:

#+begin_src elisp
  (use-package auto-capitalize
    :hook
    text-mode)
#+end_src

Note, however, that the global mode will not enable ~auto-capitalize-mode~ in major modes
where it shouldn’t: see the user option ~auto-capitalize-global-modes~. Enabling the minor
mode either manually or via a general hook will not give you that protection.

** User options

You can set the following boolean options for more fine-grained control:
   
   | Variable                                 | Default value | Description                                                                                         |
   |------------------------------------------+---------------+-----------------------------------------------------------------------------------------------------|
   | ~auto-capitalize-strings~                  | ~t~             | Capitalize strings in modes that define them                                                        |
   | ~auto-capitalize-comments~                 | ~t~             | Capitalize comments in modes that define them                                                       |
   | ~auto-capitalize-ask~                      | ~nil~           | Ask the user before automatically capitalizing anything                                             |
   | ~auto-capitalize-yank~                     | ~nil~           | Capitalize yanked text as well as typed text                                                        |
   | ~auto-capitalize-start-of-inline-comments~ | ~t~             | Capitalize the first word in inline comments. This has no effect if ~auto-capitalize-comments~ is nil |
   | ~auto-capitalize-start-of-inline-strings~  | ~nil~           | Capitalize the first word in inline strings. This has no effect if ~auto-capitalize-strings~ is nil   |
   | ~auto-capitalize-downcase-ie~              | ~t~             | Always downcase the latin abbreviation "i.e."                                                       |

More explanations are in each variable’s respective doc string.

~auto-capitalize-global-modes~ is a list of modes in which the command
~auto-capitalize-global-mode~ will enable or disable the ~auto-capitalize-mode~. By default,
this is configured to enable ~auto-capitalize-mode~ in ~text-mode~ and ~prog-mode~, and to
exclude a number of modes where =auto-capitalize.el= is known not to work, at least not
without a plugin: ~html-mode~, ~tex-mode~, etc.

~auto-capitalize-fixed-case-words~ is a list of words whose case will always be exactly how
it appears in the list. For example, the English pronoun "I" - the only default entry -
will replace any lowercase "i" followed by any character with non-word syntax.

Outside of ~auto-capitalize-fixed-case-words~, which are always forced to be in whatever
case you specify, no capitalization takes place if the word of interest happens to be
right after one of the entries in ~auto-capitalize-abbrevs~. This is a list of
abbreviations, such as "i.e." and "e.g.", which contain periods but don’t actually mark
the end of a sentence. Thus, typing "i.e. you" will not capitalize the "y".

By default, ~auto-capitalize-downcase-ie~ is ~t~, meaning that "I.e." will always be
downcased. This is meant as a workaround for the fact that typing "i.e." will, by default,
capitalize the "i", since it is contained in ~auto-capitalize-fixed-case-words~.

Note that the lists ~auto-capitalize-abbrevs~ and ~auto-capitalize-fixed-case-words~ must be
set with either ~setopt~, the ~customize~ interface, or the corresponding functions
~auto-capitalize-add-abbrevs~, ~auto-capitalize-add-fixed-case-words~,
~auto-capitalize-remove-abbrevs~, and ~auto-capitalize-remove-fixed-case-words~, otherwise
your changes will not take effect. Specifically, it is not enough to just use ~add-to-list~
to add elements to either of these variables.

Finally, for finer control, there is the core of the capitalization logic. The package
exposes two hooks as user-options: ~auto-capitalize-blocking-functions~ and
~auto-capitalize-trigger-functions~. You can add your own predicates to either of these two
hooks.

** ~auto-capitalize-blocking-functions~ and ~auto-capitalize-trigger-functions~

- ~auto-capitalize-blocking-functions~ get called first. These are predicates that take two
  arguments, ~text-start~ and ~word-start~, and return non-nil to indicate that they want to
  block capitalization in the current context. If any of these functions return non-nil,
  capitalization does not occur.

- ~auto-capitalize-trigger-functions~ get called later. These predicates take the same
  arguments as the blocking functions, and return non-nil to trigger capitalization.

Note the symmetry in semantics: a single blocking function returning non-nil will block
capitalization, whereas, assuming all blocking functions pass, a single trigger function
returning non-nil will trigger capitalization.

Note also that just because no blocking function blocks capitalization in a given context
does not mean it will occur: /at least one/ trigger function must return non-nil for
capitalization to actually happen.

By default, only ~auto-capitalize-default-blocking-function~ and
~auto-capitalize-default-trigger-function~ are included in the hooks. The companion plugins
also register their own blocking and trigger functions when you enable their respective
modes.

* How it works

The package’s main entry point is the function ~auto-capitalize-after-change~. The minor-mode
adds it to ~after-change-functions~, so it gets called as you type, delete, yank, etc. Its
job is to run the first layer of logic: it calls all functions in
~auto-capitalize-blocking-functions~, and if they all return nil, either calls
~auto-capitalize--maybe-capitalize~ if you are simply typing, or recursively analyzes
the text if you are yanking (and ~auto-capitalize-yank~ is non-nil).

~auto-capitalize--maybe-capitalize~ and ~auto-capitalize--handle-fixed-case~ are the
functions actually responsible for capitalizing words. The former checks if the word at
~word-start~ matches ~auto-capitalize--fixed-case-regexp~, which is built from
~auto-capitalize-fixed-case-words~. If it does, it calls ~auto-capitalize--handle-fixed-case~,
which simply replaces the word with its corresponding entry in
~auto-capitalize-fixed-case-words~.

Otherwise, ~auto-capitalize--maybe-capitalize~ calls ~auto-capitalize-trigger-functions~.
Those functions then check to see if capitalization is appropriate in the current context,
i.e. that the word is at the beginning of a sentence or a paragraph in text-mode, or the
beginning of a comment (if ~auto-capitalize-comments~ is non-nil), etc.

If all tests pass, voilà! Your word gets capitalized automatically.

* Writing plugins

The package is designed to be extensible to cover a number of limitations that the core
can never fully address by itself, most importantly the fact that markup languages have
their own syntax markers which should never be capitalized. For instance, the package does
not understand HTML syntax, and so will happily (and incorrectly) capitalize HTML tags.

If you’re interested in writing a plugin for some markup language, you need to do three
things:

  1. Define a blocking function. This is a predicate that takes two arguments: ~text-start~,
     the position before all open parens and quotes before the word of interest, and
     ~word-start~, the position of the first letter in the word. If it returns non-nil, it
     blocks capitalization.
  2. Define a trigger function, which takes the same arguments as the blocking function.
     It should return non-nil to trigger capitalization in the current context.
  3. Define a minor-mode that adds those functions to the appropriate hooks
     buffer-locally, and, if the plugin adds support to a major mode that
     ~auto-capitalize-global-modes~ excludes, the plugin must enable ~auto-capitalize-mode~
     itself.

The provided plugins can serve as examples of what that might look like.

* Known issues

- Even with ~auto-capitalize-tex-mode~, quoted text in ~TeX-mode~ buffers, such as
  #+begin_src TeX
    ``some text here``
  #+end_src
  does not get capitalized. This only affects the first word ("some" in the example), as
  the other rules apply as usual (beginning of a sentence, etc).

- The package struggles with markup languages in general, hence the need for plugins that
  teach ~auto-capitalize~ different markup syntaxes.

- The abbreviation "i.e." is always downcased, even if it appears at the start of a
  sentence, if the user option ~auto-capitalize-downcase-ie~ is non-nil (the default).

- On older versions of org (< 9.8), native syntax properties of src-blocks are not
  applied, which means ~auto-capitalize~ can’t capitalize comments in such blocks.

Of course, if you have ideas on how to solve any of these issues or otherwise improve the
package, PRs are more than welcome :)

* Alternatives

The modern auto-capitalization landscape in Emacs seems to have coalesced around [[https://elpa.gnu.org/packages/captain.html][captain]],
which you can get from ELPA. =auto-capitalize.el= is an alternative, based on the classic
package with the same name from all the way back in 1998. The main user-facing difference
between this package and captain is that this package tries hard to define defaults that
work out of the box, so that, ideally, you never have to write your own predicates if you
don’t want to. Captain, on the other hand, is far lighter and more efficient, and much
more modern in its approach.

* Credits & a bit of history

Kevin Rodgers wrote the original =auto-capitalize.el=. It got shared around the Emacs world
and ended up on the [[https://www.emacswiki.org/emacs/auto-capitalize.el][emacswiki]], and from there it found its way to MELPA. But MELPA removed
it for security reasons, along with other packages whose upstream was the wiki, back in
[[https://github.com/melpa/melpa/pull/5008#issue-258144843][2018]].

The [[https://github.com/yuutayamada/auto-capitalize-el][fork by Yuta Yamada]] on GitHub is the basis for this package. Although it appears
unmaintained now, the work he put into refactoring it was the starting point for this
version.

Note that this version is not fully compatible with either the original or Yuta Yamada’s
fork: the interface is different, and it drops XEmacs support entirely.
